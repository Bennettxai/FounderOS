# Writing Guide

Optimal Engine writes for the receiver, but it must preserve evidence and
structure internally.

## General Rule

```text
Store canonical objects with precise engine terms.
Render projections in the language the receiver understands.
```

## Common Genres

| Genre | Use |
| --- | --- |
| note | Lightweight captured context. |
| decision | What was decided, why, by whom, and from what evidence. |
| brief | Compact receiver-ready summary. |
| spec | Technical or operational requirements. |
| runbook | Step-by-step operational procedure. |
| review | Evaluation of state, quality, or progress. |
| transcript | Conversation or meeting record. |
| report | Structured status or findings. |

## Receiver Rules

Before rendering output, decide:

```text
Who is receiving it?
What action should they take?
What detail depth do they need?
Which sources must be visible?
What policy or permission applies?
What format should the surface use?
```

## Evidence Rule

Do not write unsupported certainty. Use clear state:

```text
Source says...
Claim pending review...
Accepted Fact...
Superseded by...
Stale after...
```

That keeps human-readable writing aligned with the governed memory lifecycle.
